# notes

Хостинг заметок: markdown приезжает по HTTP, рендерится в вёрстку «Сумерки» (тёмная
тема с янтарным акцентом, светлая по системе) и живёт по адресу `{домен}/{uuid}`. Открытого доступа нет: страницы, `/raw`,
индекс и публикация — всё за токеном, ролей две. `NOTES_READ_TOKEN` читает любую заметку,
а правит и видит в индексе только созданные им; `NOTES_ADMIN_TOKEN` может всё.

Стек: **Bun + Hono** (сервер, SSR страниц), **React + Tailwind v4** (индекс и поиск),
**SQLite** (`bun:sqlite`).

История изменений живёт в `src/web/lib/changelog.ts`: новые записи всплывают на индексе
один раз (отметка в `localStorage`), открыть заново — по иконке в шапке. Добавляя
заметную фичу, дописывай запись туда же — порядок релиза описан в проектном скилле
`.claude/skills/deploy-notes` (changelog → сборка → `./deploy.sh` → проверка → коммит).

Скилл публикации заметок нужен из любого проекта, поэтому он глобальный, но живёт здесь:
`~/.claude/skills/html-note` — симлинк на `skills/html-note`, копии нет.

## Локально

```bash
bun install
bun run build          # tsc --noEmit + vite build → dist/web, bun build → dist/server.js
bun run seed           # демо-заметки, одна из них устаревшая
bun run start          # http://localhost:3000 (из исходников)
bun dist/server.js     # то же, но из бандла — так же, как в контейнере
```

`bun run dev` поднимает vite (5173) и сервер (3000) с watch: фронт ходит в API через прокси.

Без `NOTES_ADMIN_TOKEN`/`NOTES_READ_TOKEN` доступ открыт всем — это только для локальной
разработки. При `NODE_ENV=production` сервер не стартует, пока оба токена не заданы.

В браузере токен вводится один раз в форме на закрытой странице и уезжает в httpOnly-cookie
на год: basic-auth намеренно не используется — Arc роняет его кэш и переспрашивает.

## API

| Метод | Путь | Доступ | Что делает |
| --- | --- | --- | --- |
| `GET` | `/` | read | SPA: список и поиск |
| `GET` | `/api/notes?q=&tag=&stale=1` | read* | Поиск по заголовку, тегам и тексту; устаревшие — только со `stale=1` |
| `POST` | `/api/notes` | read* | Публикация/обновление: `{markdown, title?, uuid?, tags?}` |
| `DELETE` | `/api/notes/:uuid` | read* | Удаление |
| `GET` | `/api/notes/:uuid` | read | Заметка для редактора: markdown, теги |
| `PUT` | `/api/notes/:uuid` | read* | Сохранение из редактора: `{markdown}` |
| `POST` | `/api/notes/:uuid/shares` | read | Временная ссылка: `{ttl}` в секундах, от 60 до 604800 |
| `GET` | `/api/notes/:uuid/shares` | read* | Активные ссылки заметки |
| `DELETE` | `/api/shares/:token` | read* | Отозвать ссылку |
| `POST` | `/api/images` | read | Загрузка картинки: тело — файл, тип в `content-type` (png, jpeg, gif, webp, avif; до 10 МБ). Ответ `{id, path, url}`, `path` вида `/img/<id>.png` — вставлять в markdown |
| `GET` | `/img/{id}.{ext}` | read | Картинка |
| `GET` | `/s/{token}` | — | Страница заметки по временной ссылке |
| `GET` | `/s/{token}/img/{id}.{ext}` | — | Картинка по временной ссылке, только упомянутая в этой заметке |
| `GET` | `/{uuid}` | read | Страница заметки |
| `GET` | `/{uuid}/raw` | read | Исходный markdown |
| `GET` | `/{uuid}/edit` | read | Редактор: markdown с подсветкой или визуальный режим «Вид» |
| `GET` | `/new` | read | Редактор новой заметки: на сервере она появится при первом сохранении |
| `POST` | `/auth` | — | Обмен токена на cookie (форма входа) |
| `GET` | `/robots.txt` | — | `Disallow: /` |
| `GET` | `/api/schedule?state=&tag=` | read* | Отложенные задачи агента, см. ниже |
| `GET` | `/healthz` | — | Живость + число заметок |

`read` — годится любой из двух токенов. Звёздочка: read-токен меняет лишь заметки,
которые сам и создал, и в листинге видит только их — чужие uuid из индекса не утекают;
admin правит любые и видит все. Токен принимается заголовком `Authorization: Bearer`
или cookie `notes_token`; в query — намеренно нет.

Единственный путь к заметке мимо токена — временная ссылка `/s/{token}`: её выдаёт
любой из токенов (чип «поделиться» на странице, `notes-kai share`) на срок от минуты до
7 суток, токен ссылки 43 символа base64url. Страница по ней без «править», исходника и
перехода на индекс, с `Cache-Control: private, no-store`. Истёкшая, отозванная и
несуществующая ссылки отвечают одинаковым 404, чтобы по ответу нельзя было понять, есть
ли заметка. Отозвать может admin любую, read только выданные им; удаление заметки
снимает все её ссылки. Истёкшие строки чистятся при старте и при выдаче новой ссылки.

Заголовок берётся из frontmatter (`title:`), иначе из первого `# H1` — H1 при этом
убирается из тела, его рисует шапка страницы. `uuid:` во frontmatter делает повторную
публикацию обновлением той же страницы. `stale_after: YYYY-MM-DD` задаёт дату, с
которой заметка устарела: она пропадает из индекса и счётчиков тегов, `/api/notes`
отдаёт её только со `stale=1` и считает в `staleCount`, а страница открывается как
обычно, с плашкой «Устарела с …».

«Сегодня» считается в поясе из переменной окружения `NOTES_TZ`, по умолчанию
`Europe/Moscow`. В контейнере TZ не задан, и по его часам (UTC) заметка с
`stale_after` на завтра висела бы до 03:00 МСК. Неверное имя пояса роняет старт сервера.

Теги индексируются вместе с текстом, поэтому сервисные заметки помечаются именем
сервиса (`hidden-domains`, `whois`) и находятся запросом по этому имени. `/{uuid}/raw`
отдаёт исходный markdown; агент читает опубликованное через `notes-kai get <uuid>`.

## Отложенные задачи агента

Задача — обычная заметка с тегом `agent:schedule` и датой `due: YYYY-MM-DD` во
frontmatter: с этого дня её пора выполнять. `done: YYYY-MM-DD` отмечает выполнение.
Состояние целиком лежит в markdown, отдельной таблицы нет: задачу можно завести,
перенести или закрыть и руками в редакторе.

`GET /api/schedule` отдаёт задачи по возрастанию `due` с полем `overdue_days` (0 — срок
сегодня, отрицательное — ещё не наступил). `state`: `due` (по умолчанию: не выполнены и
`due` ≤ сегодня), `open`, `done`, `all`; `tag` сужает выборку, как в индексе. «Сегодня» —
тот же `NOTES_TZ`. Read-токен видит только свои задачи.

Работать с задачами удобнее через команды задач CLI `notes-kai` (см. ниже).
`done` дописывает раздел `## Результат <дата>` и ставит `stale_after` на ту же дату:
выполненная задача уходит из индекса так же, как устаревшая заметка.

## CLI notes-kai

`cli/notes-kai.ts` собирается в один бинарник и покрывает всё, что делается с заметками
не из браузера: публикацию, чтение, поиск, удаление, временные ссылки и задачи.

```bash
bun run install:cli              # → ~/.local/bin/notes-kai
notes-kai publish note.md --pin  # опубликовать, uuid и url дописываются во frontmatter
notes-kai due --human            # что пора делать сегодня
notes-kai add task.md --due +3d  # завести задачу: due и тег дописываются во frontmatter
notes-kai done <uuid> --result 'Проверил, расхождений нет'
notes-kai --help
```

Заметки:

| Команда | Что делает |
| --- | --- |
| `publish <файл \| -> [--pin] [--uuid U] [--title T] [--tags a,b]` | Публикация; `uuid:` во frontmatter или `--uuid` обновляет ту же страницу, `--pin` дописывает `uuid:`/`url:` первыми строками frontmatter |
| `get <uuid>` | Исходный markdown любой заметки, в том числе задачи |
| `list [запрос] [--tag T]` | Поиск по опубликованному, устаревшие — с пометкой |
| `delete <uuid>` | Удаление вместе с временными ссылками |
| `share <uuid> [--ttl 1h\|1d\|7d]` | Временная ссылка без токена, по умолчанию на сутки |
| `shares <uuid>` | Активные ссылки заметки |
| `unshare <token>` | Отзыв ссылки |

Задачи — обёртки над `get` и `publish`, своих путей записи в API у них нет:

| Команда | Что делает |
| --- | --- |
| `due [--open \| --done \| --all] [--tag T]` | Очередь `GET /api/schedule`: по умолчанию невыполненные с наступившим сроком; `--open` все невыполненные, `--done` выполненные, `--all` все |
| `add <файл \| -> --due <дата> [--tags a,b]` | Ставит `due` и тег `agent:schedule` во frontmatter и публикует |
| `done <uuid> --result <текст>` | `done:`, `stale_after` и раздел `## Результат <дата>`; без `--result` текст из stdin |
| `snooze <uuid> <дата>` | Новый `due` |
| `reopen <uuid>` | Снимает `done` (и `stale_after`, если его поставил `done`) |

Служебные: `doctor` (сервер, источник токена, роль, число открытых задач) и `version`
(`git describe --tags --always` на момент сборки через `cli/build.sh`, без git и при
запуске исходника — `dev`). Вывод по умолчанию — JSON-конверт с отступом 2.
Дата — `YYYY-MM-DD`, `today`, `tomorrow`, `+3d`, `+2w`. Общие флаги: `--human`, `--json`,
`--host <url>`, `--local`.

Вывод по умолчанию — JSON-конверт `{v, command, exit, data, error}`, как у yk-kai и ci-kai;
`--human` — для глаз. Коды выхода: 0 сделано, 1 сервер не применил правку, 2 ошибка
аргументов или инструмента, 3 заметка/задача/ссылка не найдена, 4 сервер не ответил.

Токен CLI берёт сам: `$NOTES_ADMIN_TOKEN`, иначе `$NOTES_READ_TOKEN`, иначе
`sec get notes/NOTES_ADMIN_TOKEN`, иначе `sec get notes/NOTES_READ_TOKEN`
(`$NOTES_TOKEN_REF` заменяет оба sec-адреса одним). Значение токена в вывод не попадает,
`doctor` показывает только источник и длину. Правка задачи идёт тем же токеном, что и её
создание, а владелец заметки сервер пишет только при создании, поэтому ни `publish` по
uuid, ни `done`/`snooze`/`reopen` его не меняют.

## Что доступно в markdown

GFM (таблицы, списки, код) плюс **сырые HTML-блоки** — рендерер пропускает их как есть.
У блоков кода по наведению всплывает панель с кнопками «перенос» (включён по
умолчанию, кнопка возвращает горизонтальный скролл) и «копировать».
Готовые классы под вставку: `.note`, `.warn`, `.ok` (цветные врезки), `.cards` + `.card`
(сетка карточек), `kbd`. Тема страницы следует системной (`prefers-color-scheme`).

Картинки лежат в той же SQLite (таблица `images`) и вставляются относительным путём
`![подпись](/img/<id>.png)`: на странице по временной ссылке сервер сам переписывает его
на `/s/{token}/img/…`. Картинку, которую сутки не упоминает ни одна заметка, сносит
уборка при старте сервера и при следующей загрузке.

## Деплой на my-vpn

```bash
./deploy.sh              # DNS → сборка образа здесь → доставка → up → healthcheck
./deploy.sh --skip-dns   # не трогать Timeweb
./deploy.sh --logs       # плюс docker logs после деплоя
```

**Исходный код на сервер не попадает.** Туда уезжают только `compose.yml`, `.env` и
docker-образ, внутри которого лежит один `dist`: бандл сервера (`bun build --minify`,
85 КБ) и собранный фронт. Ни `src`, ни `node_modules` — из контейнера нечего вытащить
через `docker cp`. `deploy.sh` проверяет это перед отправкой и падает, если в образе
вдруг оказались исходники.

Что делает скрипт:

1. **DNS** — заводит в Timeweb поддомен `notes` и A-запись на `82.97.248.187`, если их нет.
   Чужие записи не трогает: при несовпадении IP только предупреждает. Токен берётся из
   `home-kai/TIMEWEB_TOKEN` и уходит в curl через stdin-конфиг, не через argv.
2. **Сборка** — `docker build --platform linux/amd64`, теги `latest` и `ГГГГММДД_ЧЧММСС`,
   плюс проверка на отсутствие исходников в образе.
3. **Конфиг** — `compose.yml` и `.env` из `sec export notes` ([sec](https://github.com/Kaidstor/sec) — локальный менеджер секретов; временный файл 0600,
   удаляется по выходу из функции).
4. **Образ** — `docker save` → `rsync -z` (дельтой к прошлому архиву: реально передаются
   килобайты) → `docker load` → `docker compose up -d` → архив на сервере удаляется.
5. **Откат** — на сервере остаются три последних тега: `docker tag notes:<версия> notes:latest
   && docker compose up -d` возвращает предыдущую версию.
6. **Проверка** — статус контейнера и опрос `https://notes.kaidstor.ru/healthz`
   (до минуты, пока Let's Encrypt выдаёт сертификат).

Замеры на этом проекте: сборка под amd64 ~35–45 с (эмуляция на arm64-маке), передача
дельты 3 с, `load` + рестарт ~1 с.

Роутинг описан labels'ами в `compose.yml` — traefik берёт их через docker-провайдер
(`exposedByDefault: false`, сеть `vpn`). Общий `/app/traefik/dynamic.yml`, от которого
зависят остальные сайты, деплой не редактирует.

## Скилл html-note

В репозитории есть скилл `html-note` ([skills/html-note/SKILL.md](skills/html-note/SKILL.md))
по спецификации [Agent Skills](https://agentskills.io) — инструкции агенту, как публиковать
markdown на этот сервис: сборка заметки, теги, `--pin` для обновляемых страниц, чтение
опубликованного через `notes-kai get`. Всё, что скилл делает с сервисом, идёт через CLI
`notes-kai`, так что вместе со скиллом нужен и он.

Установка (CLI сам спросит, в какого агента и куда — в проект или глобально):

```bash
npx skills add https://github.com/Kaidstor/notes --skill html-note
```

Или руками — скилл это просто папка:

```bash
cp -R skills/html-note ~/.claude/skills/
```

### Настройка

`notes-kai` ставится из репозитория: `bun run install:cli`. Токен не передаётся
аргументами и не попадает в argv/историю — CLI берёт его из окружения или из
[sec](https://github.com/Kaidstor/sec) (проект `notes`), порядок описан в разделе
«CLI notes-kai»:

| Переменная | Зачем |
| --- | --- |
| `NOTES_ADMIN_TOKEN` | всё: правка и удаление любых заметок, `list` по всем |
| `NOTES_READ_TOKEN` | чтение любой заметки, публикация и правка только своих |

```bash
notes-kai publish docs/note.md --pin --human
```

Адрес сервиса по умолчанию — `https://notes.kaidstor.ru` (`DEFAULT_HOST` в
`cli/notes-kai.ts`, или `$NOTES_HOST`); свой инстанс — флагом `--host <url>`.
